1. Pendahuluan 
1.1 Tujuan 
Software Requirements Specification (SRS) ini mendefinisikan persyaratan fungsional dan non-fungsional untuk 
EIGER Digital Store System: satu shared backend yang melayani lima aplikasi yang digunakan oleh customer dan 
staff di shop floor. Dokumen ini menerjemahkan site map / information architecture dan Product Requirements 
Document (PRD) sebelumnya ke dalam detail tingkat persyaratan yang sesuai untuk kebutuhan development, 
QA, dan technical review oleh EIGER. 
1.2 Ruang Lingkup Dokumen 
Yang termasuk dalam scope: shared CMS backend dan Admin Console terintegrasi dengan Eigerindo platform 
(CARE, IPM dan Loyalty) dan Admin Console, serta lima aplikasi yang digunakan oleh customer — Virtual Fitting 
Try-On, Table Product Knowledge, Immersive Ambience Digital, Product Catalog, dan Print Photo. 
Yang tidak termasuk dalam scope: CARE, PIM, dan Loyalty/EAC itu sendiri (dimiliki dan dioperasikan oleh EIGER), 
payment/cart processing, serta VR Game Climbing (secara eksplisit tidak termasuk dalam engagement ini). 
1.3 Target Audience 
• Development team — sebagai referensi utama untuk build scope dan acceptance criteria. 
• EIGER's IT team — untuk technical review terhadap integration points, security, dan compliance 
requirements. 
• Project stakeholders — untuk cross-check terhadap cost proposal dan PRD. 
1.4 Definisi, Akronim, dan Singkatan 
Istilah Definisi 
CARE System of record EIGER untuk data stok, harga, dan data store-zone. 
PIM Sistem Product Information Management EIGER — mengelola konten produk (gambar, 
video, deskripsi). 
EAC / Loyalty Program membership/loyalty EIGER, yang digunakan untuk memeriksa kelayakan untuk 
print. 
NAS Network Attached Storage — disediakan oleh EIGER dan berada di dalam store; menerima 
konten file-drop dari PIM. 
ROPA Record of Processing Activities — dokumentasi formal EIGER terkait compliance dan privasi 
data. 
RFID Radio-Frequency Identification — hardware tag/reader yang digunakan oleh Table Product 
Knowledge dan Immersive Ambience Digital. 
TTL Time-to-live — aturan penghapusan otomatis yang diterapkan pada foto fitting (6 jam). 
Struct Code Kode receipt/transaction yang dimasukkan pada Photo Printer untuk membantu 
mengidentifikasi session customer. 
Photo Code Kode yang diberikan kepada customer untuk mengidentifikasi foto dari fitting-session 
mereka secara spesifik.

2. Deskripsi Umum 
2.1 Perspektif Produk 
Sistem ini berada di depan tiga sistem milik EIGER — CARE, PIM, dan Loyalty/EAC — tanpa melakukan modifikasi 
terhadap sistem-sistem tersebut. Sistem ini memiliki working copy sendiri dari data katalog (disinkronkan dari 
CARE secara berkala dan di-ingest dari PIM melalui file-drop) dan menyediakan data tersebut, bersama dengan 
data session, print, serta configuration yang dihasilkan oleh sistem itu sendiri, kepada enam aplikasi melalui satu 
versioned API. 
2.2 Product Functions (Summary) 
• Melakukan sinkronisasi subset katalog EIGER yang relevan untuk store dari CARE dan PIM. 
• Memungkinkan customer mencoba produk secara virtual melalui pengalaman photobooth yang 
menggunakan AI. 
• Menampilkan detail produk yang lengkap pada permukaan meja fisik melalui RFID. 
• Mengendalikan konten video/audio ambient dalam format layar besar melalui RFID. 
• Memungkinkan customer melihat detail lengkap dari produk yang ditampilkan dan menelusuri produk 
serupa melalui tablet. 
• Memungkinkan customer mencetak hasil fitting, dengan akses yang dikendalikan berdasarkan aturan 
eligibility yang dapat dikonfigurasi. 
• Memberikan no-code Admin Console bagi store staff untuk mengelola seluruh fungsi di atas. 
2.3 Kelas Pengguna dan Karakteristik 
Kelas Pengguna Karakteristik 
Store visitor / customer 
Tidak diperlukan login untuk browsing, fitting, atau interaksi dengan table. 
Memasukkan dua kode (struct, photo) untuk melakukan print — tidak memerlukan 
akun. 
Store staff / admin Login ke Admin Console. Mengelola featured items, zones, RFID bindings, dan print 
rules. Tidak diharapkan memiliki latar belakang teknis/developer. 
EIGER's IT team Bertanggung jawab atas CARE, PIM, dan Loyalty. Menyediakan dan memelihara in-
store NAS. Menjadi counterpart teknis untuk dua live-call integrations. 
2.4 Lingkungan Operasional 
• Satu physical store, dengan satu on-site server.

• NAS yang disediakan oleh EIGER di dalam store, menerima konten file-drop dari PIM terintegrasike C. 
• RFID reader hardware pada instalasi Table Expedition Hub dan LED Dynamic Content. 
• Dedicated GPU workstation yang menjalankan AI fitting pipeline. 
• Kiosk/tablet/TV touchscreens untuk AI Fit & Go, Table Expedition Hub, Interactive Display, dan Photo 
Printer; serta large-format display untuk LED Dynamic Content. 
• Physical photo printer yang terhubung dengan aplikasi Photo Printer. 
2.5 Batasan Desain dan Implementasi 
• Read-only terhadap CARE, PIM, dan Loyalty untuk seluruh data katalog dan membership — tidak memiliki 
akses write ke sistem EIGER mana pun, dalam kondisi apa pun. 
• Tidak terdapat fungsi payment atau cart/checkout di seluruh sistem — secara eksplisit berada di luar 
scope, sehingga sistem tetap berada di luar cakupan PCI-DSS. 
• Menggunakan single server tanpa failover yang saat ini dirancang — jika server mengalami downtime, 
seluruh enam aplikasi akan berhenti beroperasi. 
• NAS hardware disediakan oleh EIGER dan tidak termasuk dalam biaya proyek ini. 
2.6 Asumsi dan Dependensi 
• Store ini hanya menerima sebagian dari seluruh katalog EIGER, yang telah difilter terlebih dahulu di sisi 
EIGER sebelum masuk ke sistem ini. 
• CARE, PIM, dan Loyalty/EAC tetap tersedia dan API tetap stabil selama sistem ini beroperasi; sistem ini 
tidak mengontrol uptime dari sistem-sistem tersebut. 
• Mekanisme autentikasi untuk dua live-call integrations (real-time stock/price dan transaction lookup) akan 
dikonfirmasi bersama tim IT EIGER. 
• PIM file-drop mencakup keseluruhan data (gambar, video, produk). 
3. Fitur Sistem (Persyaratan Fungsional) 
Persyaratan dikelompokkan berdasarkan aplikasi, sesuai dengan Information Architecture yang telah disetujui. 
Setiap persyaratan diberi nomor untuk traceability (misalnya, FR-FIT-03) dan harus direferensikan secara 
langsung dalam QA test cases. 
3.1 CMS Backend & Admin Console 
Admin Console merupakan control surface yang digunakan oleh staff untuk mengelola seluruh aplikasi lainnya. 
Sesuai dengan site map / IA, homepage menyediakan akses ke area konfigurasi untuk masing-masing aplikasi, 
serta bagian Monitoring dan User Management yang berlaku di seluruh sistem. 
FR-CMS-01 Sistem harus menyediakan homepage yang menghubungkan ke area konfigurasi untuk Table 
Expedition, AI Fit & Go, Interactive Display, LED Dynamic Content, Photo Printer, Monitoring, dan User 
Management. 
FR-CMS-02 Untuk setiap aplikasi berbasis produk, Admin Console harus memungkinkan staff mengonfigurasi 
nama produk, product stats, product image path, kategori/activity, RFID-to-product mapping jika berlaku, 
serta status mapping tanpa perubahan kode atau keterlibatan developer. 
FR-CMS-03 Sistem harus memungkinkan staff untuk mengatur visibilitas item (show/hide) dan item-zone 
assignment (misalnya berdasarkan lantai) untuk AI Fit & Go. 
FR-CMS-04 Sistem harus memungkinkan staff untuk mengatur similar-product / recommended-product 
mappings untuk AI Fit & Go dan Interactive Display. 

===== PAGE 5 =====
FR-CMS-05 Sistem harus memungkinkan staff untuk mengatur konten ambience video/audio dan RFID-to-
item mapping, termasuk default dan idle-state ambience, untuk LED Dynamic Content. 
FR-CMS-06 Sistem harus memungkinkan staff untuk mengatur Print Rules (minimum transaction requirement, 
EAC membership requirement, atau keduanya) yang digunakan oleh Photo Printer. 
FR-CMS-07 Bagian Monitoring harus menampilkan setidaknya total product count, total items per zone, dan 
total RFID tag count, dengan CRUD history yang dibatasi hanya untuk user superadmin. 
FR-CMS-08 Sistem harus menyediakan User Management dengan role-based access control (RBAC) yang 
terpisah dari customer-facing flows. Super Admin harus dapat membuat, mengubah, menonaktifkan user, 
serta mengatur role dan permission aksesnya. 
  
  
3.2 Virtual Fitting Try-On (AI Fit & Go) 
Sesuai dengan site map / IA: Product Screen → Start → Consent Screen → Photo Capture → Item Selection → 
Item Result → Background Selection → Background Result → Final Result → Email Input → Finish, dengan jalur 
retake pada setiap tahap capture/result. 
  
Consent bukan merupakan gate pada experience — setiap customer tetap menyelesaikan seluruh flow terlepas 
dari jawabannya. Consent menentukan apakah hasil akan disimpan di server dan kemudian dapat di-print, atau 
hanya dikirim melalui email dan tidak pernah disimpan secara permanen. 
FR-FIT-01 Sistem harus menampilkan Product Screen yang menjadi titik awal customer untuk memulai fitting 
flow. 
FR-FIT-02 Sistem harus menampilkan consent screen sebelum Photo Capture, yang memungkinkan customer 
untuk menerima atau menolak consent. Penolakan TIDAK boleh menghambat customer untuk melanjutkan ke 
Photo Capture atau step berikutnya. 
FR-FIT-03 Fitting flow (Photo Capture, Item Selection, Background Selection, Final Result) harus berjalan 
secara identik terlepas dari pilihan consent customer. 
FR-FIT-04 Sistem harus melakukan live stock/price check terhadap CARE saat Product Screen dibuka, dengan 
melewati local cache, serta menyediakan timeout/fallback sehingga response yang terlambat tidak 
menghambat flow. 
FR-FIT-05 Sistem harus memungkinkan customer untuk melakukan capture foto dan memilih untuk 
melanjutkan (Next) atau melakukan retake sebelum melanjutkan. 
FR-FIT-06 Sistem harus menampilkan item-selection screen dan menghasilkan AI fitting result yang 
merefleksikan item yang dipilih, dengan retake path kembali ke item selection. 
FR-FIT-07 Sistem harus menampilkan background-selection screen dan menghasilkan AI result yang 
merefleksikan background yang dipilih, dengan retake path kembali ke background selection. 
FR-FIT-08 Sistem harus menampilkan Final Result screen yang menggabungkan item dan background yang 
dipilih. 
FR-FIT-09 Sistem harus mengumpulkan email customer terlepas dari pilihan consent, karena email merupakan 
satu-satunya delivery channel bagi customer yang menolak consent. 
FR-FIT-10a Jika consent diberikan: saat Finish, sistem harus menyimpan session dan final image ke database, 
menerbitkan photo code yang terkait dengan session tersebut, dan menyediakan code tersebut kepada 
customer (melalui on-screen dan/atau email) untuk digunakan kemudian di Photo Printer. 

===== PAGE 6 =====
FR-FIT-10b Jika consent ditolak: saat Finish, sistem TIDAK boleh menyimpan session atau image ke database 
dan TIDAK boleh menerbitkan photo code. Sistem hanya akan mengirimkan final image kepada customer 
melalui email. 
FR-FIT-11 Untuk session yang memberikan consent, sistem harus menetapkan retention cut-off pada pukul 
23.59 waktu lokal store pada hari foto dibuat. Seluruh input photo, hasil generate AI, dan turunannya harus 
dihapus otomatis pada cut-off tersebut, terlepas dari status print. Session yang menolak consent tidak 
menyimpan image secara permanen. 
FR-FIT-12 Untuk session yang memberikan consent, sistem harus mengaitkan session dengan product(s) yang 
dicoba, untuk digunakan kemudian oleh eligibility check pada Photo Printer. 
FR-FIT-13 Customer yang menolak consent tidak dapat mengambil atau mencetak hasil mereka melalui Photo 
Printer, karena tidak ada session atau photo code yang dibuat untuk kunjungan tersebut — email menjadi 
satu-satunya cara bagi customer untuk menerima image. 
FR-FIT-14 Berdasarkan hasil pengujian yang disepakati, minor error pada hasil generate AI maksimal 5% dan 
major error harus 0%. Perubahan wajah atau bentuk tubuh customer diklasifikasikan sebagai major error dan 
tidak boleh diterima pada hasil final. 
3.3 Table Product Knowledge (Table Expedition Hub) 
Sesuai dengan site map / IA: Idle Screen → Scan RFID → Home → (product name / available size / available 
colors / More Detail / product suggestions), dengan Item Lost path yang kembali ke Idle. 
FR-TABLE-01 Sistem harus menampilkan Idle Screen ketika tidak ada item yang terdeteksi, dan harus kembali 
ke screen tersebut jika item yang diletakkan di atas meja diambil (“Item Lost”). 
FR-TABLE-02 Sistem harus mendeteksi item yang memiliki RFID tag yang diletakkan di atas meja dan 
berpindah ke Home screen untuk produk tersebut. 
FR-TABLE-03 Home screen harus menampilkan product name, available size, dan available colors, serta 
menyediakan aksi More Detail dan aksi product suggestion. 
FR-TABLE-04 Sistem harus menampilkan hingga lima similar-product suggestions, yang bersumber dari 
konfigurasi similar-product pada Admin Console. 
FR-TABLE-05 More Detail screen harus menampilkan General Information (nama, harga, ukuran, stok, dan 
gambar), description, feature, technical details, Ideal For, video, serta informasi lain yang tersedia dari PIM 
dan CARE. Informasi yang tidak tersedia tidak ditampilkan. 
FR-TABLE-06 Sistem harus menyediakan AI Summary untuk produk pada More Detail path. 
FR-TABLE-07 Sistem harus menyediakan Usage Instructions screen yang dapat diakses dari Idle, serta 
menyediakan aksi Back dari setiap sub-screen untuk kembali ke screen sebelumnya. 
3.4 Immersive Ambience Digital (LED Dynamic Content) 
Sesuai dengan site map / IA: Idle Screen (video + audio) → RFID Scan (1/2/3) → Ambience scene yang sesuai 
(video + audio) → Item Lost kembali ke Idle. 
FR-AMB-01 Sistem harus memutar idle ambience video dan audio yang telah dikonfigurasi ketika tidak ada 
item RFID yang terdeteksi. 
FR-AMB-02 Saat mendeteksi RFID tag yang telah dikonfigurasi, sistem harus berpindah ke ambience scene 
yang sesuai dan memutar video serta audio yang telah dikonfigurasi. 
FR-AMB-03 Sistem harus kembali ke Idle Screen ketika item yang terdeteksi diambil. 
FR-AMB-04 Admin Console harus memungkinkan staff untuk mengonfigurasi konten video/audio dan RFID-to-
scene mapping untuk setiap ambience scene, termasuk idle dan default states.

3.5 Product Catalog (Interactive Display) 
Sesuai dengan site map / IA: Featured Product Screen → Recommendation → Product Suggestion Screen → 
individual Product screens, dengan 2-minute no-action timeout yang mengembalikan ke state sebelumnya, serta 
Home action yang tersedia di seluruh flow. 
FR-CAT-01 Sistem harus menampilkan Featured Product Screen yang secara default menampilkan produk 
utama sesuai konfigurasi CMS, beserta General Information, gambar, harga, ukuran, warna, dan status stok 
yang tersedia. 
FR-CAT-02 Sistem harus menyediakan aksi Recommendation yang mengarah ke Product Suggestion Screen 
yang menampilkan daftar produk yang tersedia beserta ketersediaan stock. 
FR-CAT-03 Setiap produk dalam daftar suggestion harus dapat dibuka ke Product Screen yang menampilkan 
nama dan stats produk tersebut, serta menyediakan aksi Back. 
FR-CAT-04 Sistem harus kembali ke Featured Product Screen setelah 2 menit tanpa interaksi dari Product 
Suggestion Screen atau individual Product Screen. 
FR-CAT-05 Sistem harus menyediakan aksi Home yang langsung kembali ke Featured Product Screen dari 
Product Suggestion Screen. 
3.6 Print Photo (Photo Printer) 
Sesuai dengan site map / IA (post-review revision): Struct Code entry → Photo Code entry → Eligibility Check → 
Confirmation → Photo Preview → Print, dengan 2-minute no-action timeouts dan Decline paths yang kembali ke 
code entry. 
FR-PRINT-01 Sistem harus menyediakan input form untuk struct (receipt/transaction) code, dengan aksi 
Submit. 
FR-PRINT-02 Sistem harus menyediakan input form kedua untuk photo code, dengan aksi Submit. 
FR-PRINT-03 Setelah kedua code dikirimkan, sistem harus mengevaluasi Print Rules yang sedang dikonfigurasi 
(minimum transaction, EAC membership, atau keduanya) sebelum menampilkan Photo Preview. 
FR-PRINT-04 Jika minimum-transaction rule aktif, sistem harus memverifikasi jumlah transaksi melalui live 
lookup ke CARE menggunakan struct code. 
FR-PRINT-05 Jika EAC-membership rule aktif, sistem harus memverifikasi status membership melalui live 
check ke Loyalty/EAC. 
FR-PRINT-06 Jika eligibility check gagal, sistem harus menampilkan pesan not-eligible yang jelas kepada 
customer dan tidak melanjutkan ke Photo Preview. 
FR-PRINT-07 Jika eligibility check berhasil, sistem harus menampilkan Confirmation Dialog Box sebelum 
menampilkan Photo Preview. 
FR-PRINT-08 Sistem harus kembali ke Struct Code entry jika customer menolak pada tahap code-entry atau 
preview confirmation. 
FR-PRINT-09 Sistem harus kembali ke code entry setelah 2 menit tanpa interaksi pada tahap photo-code atau 
photo-preview. 
FR-PRINT-10 Saat Print, sistem harus mencatat print job yang mereferensikan session, code yang digunakan, 
konfigurasi rule yang berlaku, dan hasil eligibility. 
FR-PRINT-11 Sistem dapat mengirimkan receipt/confirmation email setelah print berhasil dengan batasan 1x 
print per customer, sesuai dengan kebutuhan EIGER.

5. Persyaratan Non-Fungsional 
Kategori Persyaratan 
Performa 
Hasil Virtual Fitting Try-On harus tampil dalam waktu 5–10 detik setelah capture. Detail 
Table Product Knowledge harus tampil dalam waktu 1–2 detik setelah RFID terdeteksi. 
Catalog sync harus selesai dalam setiap siklus 5–15 menit. 
Ketersediaan 
Data katalog yang di-cache (Table Product Knowledge, LED Dynamic Content, Interactive 
Display) harus tetap tersedia jika CARE atau PIM sementara tidak dapat diakses. Deployment 
menggunakan single-server tanpa failover; gangguan penuh pada server akan memengaruhi 
seluruh enam aplikasi. 
Keamanan 
Tidak ada inbound network exposure dari CARE atau PIM untuk catalog sync. Mekanisme 
autentikasi untuk dua live-call integrations (API key / OAuth2 / mTLS) akan dikonfirmasi 
bersama EIGER IT.

Kepatuhan  
Foto fitting-session harus dihapus paling lambat 6 jam setelah capture, tanpa pengecualian. 
Explicit consent harus diperoleh sebelum foto apa pun diambil. Logging harus dibuat secara 
terstruktur untuk mendukung dokumentasi ROPA EIGER. 
Integritas Data Sistem tidak boleh membuat, memperbarui, atau menghapus data di CARE, PIM, atau 
Loyalty/EAC. 
Kemudahan 
Penggunaan 
Staff store harus dapat melakukan seluruh tugas konfigurasi Admin Console (Section 3.1) 
tanpa keterlibatan developer. Customer-facing flows (Table Expedition Hub, LED Dynamic 
Content, Interactive Display, Photo Printer) tidak boleh memerlukan login, selain jika 
diperlukan, dengan memasukkan codes. 
Pemeliharaan Print eligibility rules harus dapat diubah oleh staff dan berlaku secara langsung tanpa 
memerlukan deployment. 
6. Kebutuhan Data 
Core entity yang di-maintain oleh backend, dikelompokkan berdasarkan origin: 
Catalog data (from CARE + PIM) 
• Products — name, category, image, material, description, featured flag, discontinued flag, last-updated 
timestamp. 
• Sync State — last sync cursor, timestamp, dan status, yang mengolah health-check endpoint. 
• Zones / Product-Zone mapping — di-source dari zone data milik CARE. 
Session data (generated by this system) 
• Fitting Sessions — input photo, output yang di-generate AI, background yang dipilih, consent flag, 
scheduled deletion time, status. 
• Fitting Session Items — menghubungkan setiap session ke product yang dicoba. 
• RFID Tags — me-map tag fisik ke product; di-share oleh Table Expedition Hub dan LED Dynamic Content. 
Print flow data 
• Print Rules — single configurable record: minimum-transaction requirement, EAC-membership 
requirement, di-enable/disable secara independen. 
• Print Jobs — session reference, struct/photo code yang digunakan, EAC dan transaction reference yang di-
check, eligibility outcome, print timestamp. 
7. Gambaran Umum Arsitektur Sistem 
Backend diorganisir sebagai lima proses terpisah secara logis dalam satu server: CARE Sync (poll API terjadwal), 
PIM Folder Watcher (memindai NAS yang disediakan EIGER untuk file-drop content, tanpa API call), Core API 
(single interface yang digunakan setiap aplikasi), Real-Time Query Path (digunakan hanya oleh Virtual Fitting Try-
On dan Print Photo untuk live check), Consent & Retention Job (menjalankan aturan photo deletion setiap jam 
23.59), dan Admin Console. Diagram arsitektur lengkap dan detail tingkat komponen disediakan dalam dokumen 
Infrastructure Overview pendamping.
